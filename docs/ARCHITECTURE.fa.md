# معماری فیت‌فلو

## مرزهای سیستم

- `apps/web`: اپ React راست‌چین و PWA
- `apps/api`: API مبتنی بر Hono و Better Auth
- `packages/db`: مدل Drizzle، اتصال `pg` و migration
- `packages/contracts`: اعتبارسنجی Zod و قراردادهای مشترک

## تصمیم مهم مدل داده

قالب برنامه (`workout_plans`) از اجرای واقعی (`workout_sessions`) جدا است. آیتم‌های برنامه نیز عنوان
و توضیح حرکت را snapshot می‌کنند؛ بنابراین تغییر کتابخانه حرکات، گزارش‌های قبلی را بازنویسی نمی‌کند.

## رسانه

فایل‌ها مستقیماً با presigned URL در MinIO/S3 قرار می‌گیرند. PostgreSQL فقط metadata و کلید فایل را
نگه می‌دارد. در محیط production، bucket گزارش‌های جسمانی باید private و URLهای نمایش نیز signed
باشند.

## آفلاین

App shell و داده‌های خواندنی توسط service worker cache می‌شوند. عملیات Todo هنگام قطع اینترنت در
IndexedDB وارد outbox می‌شوند و با رویداد `online` دوباره ارسال خواهند شد. `clientMutationId` برای
جلوگیری از اجرای تکراری در مدل داده وجود دارد.

## مجوز دسترسی

- role از session سمت سرور خوانده می‌شود.
- مربی تنها زمانی به شاگرد دسترسی دارد که رابطه فعال در `coach_students` موجود باشد.
- مالکیت حرکت پیش از ثبت فایل رسانه بررسی می‌شود.
- شاگرد فقط session و گزارش‌های متعلق به خودش را دریافت می‌کند.
